# style-review

writing-kitのguidelineと照合して、逸脱箇所を指摘し、修正案を出す。共通ルールは`common_guideline.md`、本文の文体は`style_desu_masu.md`または`style_da_dearu.md`、design noteの形式は`design_note_guideline.md`が定める。

## 前提

- 本skillと同じディレクトリのguidelineファイルを必ず読み込む：
    - 対象が何であれ → `guidelines/common_guideline.md`
    - 本文（散文）が対象 → 加えて、対象の文体に応じた `guidelines/style_desu_masu.md` または `guidelines/style_da_dearu.md`。文体は対象文章の文末から自動判別し、判別できない場合（短い断片など）はユーザーに質問する
    - design note（bullet構造）が対象 → 加えて `guidelines/design_note_guideline.md`
    - 本文とdesign noteが混在している場合は、両方読み込んで該当箇所ごとに照合する

## 進め方

1. **対象を判定する**。ユーザーから渡された文章が本文なのか、design noteなのか、混在しているのかを判定する。ファイルパスや貼り付けられたテキストから判別する。本文の場合は文体（です・ます調／だ・である調）も判別する。判別不能な場合は質問する

2. **guidelineを読み込む**。判定結果に応じて対応するguidelineを読む

3. **項目ごとに照合する**。guidelineの各ルールに対して、対象文章のどこが合致・逸脱しているかをチェックする。

    共通（本文・design noteの両方で見る。common_guidelineに対応）：
    - 認識の帰属（意見の一般論へのすり替え、定説・研究の帰結・自分の推論の書き分け、儀式的なエクスキューズの禁止、実質的な留保）
    - 命題・概念の扱い（空虚な形容・流行語の禁止、見立てのラベル化禁止、自作区分のマトリクス演出禁止）
    - 修辞（語りかけ・問いかけ・見得を切る演出・予告総括の型の禁止、先回り訂正）
    - 論の進め方（セクション間のつなぎの位置、概念・具体例の再利用、形式的まとめの禁止）
    - 引用・出典（Author (Year)形式、参考文献の書式、書名『』、URL表記）
    - 表記（漢字/かなの使い分け、英語術語、カタカナ、「」/ "" /『』の使い分け、中黒、括弧、句読点、数字）
    - Markdown（見出し階層、太字・イタリック・絵文字・記号・表の禁止）

    本文の場合はさらに（文体別guidelineに対応）：
    - 文体（文末の基本形、一人称の扱い）
    - 語り口（口語的なゆるさの扱い、ヘッジの表現形、提案の抑制、段落の締め、文末表現の混在）
    - 段落の作り方（3〜6文、ぶつ切りの禁止）
    - つなぎ・参照の言い回し（接続語、前内容への参照、ロードマップ文）
    - 本文中の箇条書き（だ・である調/体言止め、句点の扱い、箇条書きと散文の使い分け、箇条書きの形式）

    design noteの場合はさらに（design_note_guidelineに対応）：
    - 基本形式（1行1命題、複数トピックの同居禁止、だ・である調/体言止め、句点なし、本文文章そのものを書かない、用語導入形式、補足の子bullet化、執筆メタ記述の禁止）
    - 並び順とブロック（論証順、空行区切り）
    - 本文中への配置（ラベル・HTMLコメント禁止、区切り記号の扱い）
    - ネスト（子bulletの役割）
    - 文献・出典の書き方

4. **レポートする**。逸脱の重要度が高いもの・件数が多いものから順に整理して出す。各指摘は以下を含める：
    - 逸脱箇所（原文引用または行番号）
    - どのルールに反しているか（guidelineの該当項目）
    - 修正案

## 注意

- guidelineで明示的に許容されているもの（漢字/かなの文脈依存的な変化、実質的な情報を持つ留保、文献由来の隠喩術語など）は逸脱として扱わない
- 逸脱の指摘は「機械的な違反検出」ではなく、なぜそのルールがあるかを踏まえた文脈的判断で行う。ルールと衝突するように見えても文脈上正当な選択なら指摘しない
- 文体の判別を誤ったまま照合しない。です・ます調の文章にstyle_da_dearuを当てる（またはその逆）と指摘が全て誤りになるため、判別に少しでも迷いがあればユーザーに確認する
- 全ての逸脱を一度に出すと大量になる場合は、優先度の高い5〜10件程度から先に提示し、残りは分類ごとにまとめて追加する形にする
- 修正案は複数の選択肢を提示できる場合は提示する（例：「〜てみる」を「〜てみる」のままにするか、「〜しに行く」に置き換えるか等）
