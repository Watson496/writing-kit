# design-note

writing-kitの`design_note_guideline.md`に沿って、本文執筆前の論証設計図（design note）を作成する。

## 目的

design noteは本文の下書きではなく、論証の設計図。ここで論の流れと素材の配置を確定させ、言い回しは本文執筆時に考える。

## 前提

- 本skillと同じディレクトリの `guidelines/design_note_guideline.md` を必ず読み込む
- 本文の文体感覚が必要な場合は `guidelines/style_guideline.md` も参照する

## 進め方

1. **文脈を確認する**。ユーザーから受け取った情報を整理する — トピック、既存の下書きやメモ、対象読者、書きたい節の位置づけ、想定する媒体（Confluence / developers blog / noteなど）。不足している情報があれば質問する

2. **論の流れを決める**。使う素材（具体例、文献、引用、実データ）を洗い出し、大まかな流れに落とし込む。全体の流れは記事の性質に応じて変わる — 課題提起 → 状況確認 → 知見導入 → 適用 → 帰結、といった型もあれば、経緯の時系列に沿った型、事例の列挙型なども採り得る

3. **bulletを書く**。design_note_guidelineの基本形式に従って1行1命題で書く。文体はだ・である調または体言止め、句点なし。用語導入は「用語：説明」形式でOK

4. **並び順を整える**。bulletを上から下に読んで本文の論証が追える順に並べる。空行でブロックを区切り、1ブロックが本文の1つの論のまとまり（数段落〜小節）に対応する形にする

5. **ネストを整理する**。子bulletは親bulletの命題に対する列挙・詳細・根拠にのみ使う。論証の次のステップを子にしない（次のステップは同じ階層の次のbullet）

6. **自己チェック**。以下を満たしているか確認する：
    - 1行に1命題だけ、複数トピックが同居していない
    - 補足を「 — 」で同じ行に繋いでいない（子bulletとして階層化する）
    - 「〜の提示」「〜のまとめ」「〜で結ぶ」のような執筆行為のメタ記述が入っていない
    - 文献の導入と内容の要約が同じbulletに入っていない（文献導入は「著者『書名』」のみ、内容は子bulletに）
    - design noteであることを示すラベルやHTMLコメントが付いていない

## 出力

- design noteのbulletそのものを出力する（前置きの説明文を長々と付けない）
- 節見出しの直下に置く形で出す場合は、見出し自体が区切りになるので区切り記号を付けない
- 書きかけの本文の続きに置く形で出す場合は、本文とdesign noteのあいだを `---`（水平線）で区切る

## 進め方の注意

- 一度に全体を出して終わり、ではなく、ユーザーと対話しながら流れを詰めていくのが基本
- 素材が不足していると感じたら「この論点にはどういう具体例を当てる想定か」等を聞く
- 論の流れに複数の型が考えられる場合、選択肢を提示してユーザーに選んでもらう
