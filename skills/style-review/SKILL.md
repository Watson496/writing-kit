# style-review

writing-kitの`style_guideline.md`（本文の場合）または`design_note_guideline.md`（design noteの場合）と照合して、逸脱箇所を指摘し、修正案を出す。

## 前提

- 本skillと同じディレクトリのguidelineファイルを必ず読み込む：
    - 本文（散文）が対象 → `guidelines/style_guideline.md`
    - design note（bullet構造）が対象 → `guidelines/design_note_guideline.md`
    - 両者が混在している場合は、両方読み込んで該当箇所ごとに照合する

## 進め方

1. **対象を判定する**。ユーザーから渡された文章が本文なのか、design noteなのか、混在しているのかを判定する。ファイルパスや貼り付けられたテキストから判別する。判別不能な場合は質問する

2. **guidelineを読み込む**。判定結果に応じて対応するguidelineを読む

3. **項目ごとに照合する**。guidelineの各ルールに対して、対象文章のどこが合致・逸脱しているかをチェックする。本文の場合は以下の分類で見る：
    - 文体（本文のです・ます調、箇条書きのだ・である調/体言止め、句点の扱い、一人称、読者への語りかけ）
    - 語り口・言い回し（話し言葉のゆるさ、ヘッジ表現の使い分け、儀式的なエクスキューズの禁止、実質的な留保、決め台詞の禁止、見立てラベル化の禁止、問いかけの禁止、文末表現の混在、接続語）
    - 論の進め方（セクション間のつなぎ、概念・具体例の再利用、自作区分をマトリクスに演出しない、ロードマップ文、形式的まとめの禁止）
    - 引用・出典（Author (Year)形式、参考文献の書式、本文中の書名『』、URL表記）
    - 表記（漢字/かなの使い分け、英語術語、カタカナ、「」/""/『』の使い分け、中黒、括弧、句読点、数字）
    - Markdown（見出し階層、箇条書きと散文の使い分け、太字・イタリック・絵文字・記号・表の禁止）

    design noteの場合は：
    - 基本形式（1行1命題、複数トピックの同居禁止、だ・である調/体言止め、句点なし、本文文章そのものを書かない、用語導入形式、補足の子bullet化、執筆メタ記述の禁止）
    - 並び順とブロック（論証順、空行区切り）
    - 本文中への配置（ラベル・HTMLコメント禁止、区切り記号の扱い）
    - ネスト（子bulletの役割）
    - 文献・出典の書き方

4. **レポートする**。逸脱の重要度が高いもの・件数が多いものから順に整理して出す。各指摘は以下を含める：
    - 逸脱箇所（原文引用または行番号）
    - どのルールに反しているか（guidelineの該当項目）
    - 修正案

## 注意

- guidelineで明示的に許容されているもの（漢字/かなの文脈依存的な変化、実質的な情報を持つ留保、文献由来の隠喩術語など）は逸脱として扱わない
- 逸脱の指摘は「機械的な違反検出」ではなく、なぜそのルールがあるかを踏まえた文脈的判断で行う。ルールと衝突するように見えても文脈上正当な選択なら指摘しない
- 全ての逸脱を一度に出すと大量になる場合は、優先度の高い5〜10件程度から先に提示し、残りは分類ごとにまとめて追加する形にする
- 修正案は複数の選択肢を提示できる場合は提示する（例：「〜てみる」を「〜てみる」のままにするか、「〜しに行く」に置き換えるか等）
